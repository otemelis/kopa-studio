# Kopa ASO Product UX Plan

## Product Goal

Kopa should feel like a weekly ASO operating system for a small studio: clear scope, trustworthy evidence, and a short path from signal to action.

## Priority 1: Working Context and Keyword Operations

Status: complete

- Add a compact shared app scope and collection-status context to the ASO shell.
- Add persistent local saved Keyword views for repeated weekly cuts of the portfolio.
- Add bulk keyword selection with priority and pause actions.
- Keep the existing filters, sorting, above-table add flow, and individual edit flow intact.

Success measure: a user can open a relevant app scope, load a saved view, and update a group of terms without manually repeating filters or opening each row.

## Priority 2: Insight Triage

Status: in progress

- Collapse evidence until requested and lead with signal, confidence, impact, and next action.
- Route each rule type to the right destination: Sync, Keywords, Competitors, or an experiment draft.
- Group high-volume metadata opportunities by market and theme.

## Priority 3: Decision-First Briefing

Status: complete

- Limit the primary action queue to three decisive items.
- Group remaining signals and make each action outcome explicit.
- Separate alert preferences from the weekly decision surface.

## Priority 4: Evidence Workspaces

Status: planned

- Merge competitor change feeds into one filterable timeline with a concise landscape view.
- Turn review topics into a trend and triage workflow.
- Put active experiments, review dates, and decision readiness ahead of the experiment archive.

## Priority 5: Operational Detail

Status: planned

- Keep one recommended action prominent in Sync.
- Move raw run logs and technical errors into progressively disclosed operational detail.
- Translate recurring collection errors into affected terms/markets and a direct recovery path.

## Product Principles

1. Scope is always visible: app, market where relevant, and data confidence.
2. A screen leads with one decision, not every available dataset.
3. Bulk work is the default once a portfolio grows beyond a few terms.
4. Technical detail is available, but never competes with the next useful action.
