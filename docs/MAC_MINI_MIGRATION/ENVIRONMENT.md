# Credentials and environment contract

**Names and placement only; no values are in this handover.** The Vercel connector was queried with decryption disabled. Provision credentials afresh on the Mac mini after worker code and access scope are reviewed. Do not copy `.env.local`, Vercel CLI auth, Supabase sessions, `.p8`, Keychain exports or tokens between Macs or into Git/archives. A sanitized empty template is in the separate archive manifest.

The root Vercel project currently has `CRON_SECRET`, ASC reader/setup credentials, `SUPABASE_SERVICE_ROLE_KEY` and Supabase URL/anon names configured. Tools has Apple Ads v1/v5, reader, Vercel Analytics, Supabase and cron names configured. This confirms **configuration names**, not secret validity or access scope. Never print or paste a value during inventory.

For a future Mac worker, prefer an owner-approved dedicated Keychain service name per source and a short wrapper that retrieves values at runtime without logging them. Restrict the worker account and its log directory (`umask 077`, `chmod 700`). Keep secret values out of `ProgramArguments`, `EnvironmentVariables`, crash reports and process command lines. A Keychain-backed user LaunchAgent requires the worker account's login Keychain to be available after reboot; test that explicitly before cutting over. If that cannot be guaranteed, choose a separately reviewed secure secret store, not plaintext in a LaunchDaemon plist. Rotate credentials on the old host only after each new worker proves parity and Vercel rollback is no longer needed.

Supabase project `dsjgbxkerucutrjltgws` is shared with POIS, PASSPORT and other apps. The current `service_role` can bypass RLS and is too broad for a permanent Mac worker. Do not grant new SQL roles, alter RLS or issue tokens in this phase. The migration worker PR should specify exact table/RPC permissions and get separate authorization before production credential creation.
