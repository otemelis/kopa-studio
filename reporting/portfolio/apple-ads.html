Reconciliation and source definitions

Console CSV campaign sums match the source footer, which is excluded from campaign rows. Saved API snapshots retain exact source decimals; displayed EUR amounts round to cents after aggregation. API totals include observed rows only, and absent campaigns remain unavailable. API CPA divides exact spend by total attributed installs before rounding to cents. Console CPA divides source spend by total attributed installs, and is unavailable with no attributed installs. Total installs are not added to tap-through installs: the latter is a component of the total.

Reconciliation applies only to the supplied console control periods listed in each API snapshot. A full-window control validates reported count sums and cent-rounded spend for that window; it does not independently verify the stored campaign inventory, missing API rows, daily allocation or attribution accuracy. Explicit console zeros remain source-reported zeros; absent API rows remain unavailable.

The period and API query time are shown above separately from the local import time. These are saved reports; neither an import nor a page reload queries Apple Ads. No historical database records are overwritten. Purchases, revenue and paying-customer attribution remain unavailable.

Seven-day comparisons require the same observed campaigns and complete daily rows in both weeks. Missing campaigns stay unavailable; this is not an account-wide comparison. Spend changes use exact source decimals before rounding, so they can differ from subtraction of rounded display amounts.

POIS, PASSPORT and LoveType are not present in these supplied reports. No zero activity is inferred for them. CSV campaign statuses describe that export, not current delivery. API row statuses describe whether data was returned, not campaign delivery. No bids, budgets or campaigns were changed.
